## 3. 取得の方法と守った作法
- 取得は `curl` で行った。環境の外向き通信は許可リスト方式のプロキシを通る。ブラウザの偽装はしておらず、User-Agent は `research-fetch/1.0` の固定である。WebFetch ツールは許可の追加後も失敗した（ツール側の問題）ため使っていない。
- 間隔は約 0.7 秒以上、1 担当あたり 200 回以内、失敗した取得の再試行は同じ URL につき 2 回までを方針とした。国立国会図書館サーチは同時アクセスに上限があり、応答の約半数が HTTP 429 だった。担当は Bulkowski の検索を 7 回試して方針を超え、取りまとめ役の指示で打ち切った。また、取得の待ち行列を誤って二重に起動した時間帯（06:30〜06:35 UTC ごろ）があり、429 を増やした可能性がある（詳細は [02_ndl_cinii_jstage.md](02_ndl_cinii_jstage.md)）。
- 取得物は信頼できないデータとして扱った。専用の空のディレクトリに保存し、解析は Python の隔離モード（`-I`）で行い、取得物に含まれる内容は実行していない。
- すべての取得物に sha256 を付け、URL・取得時刻（UTC）・HTTP 状態・バイト数とともに取得ログへ残した。リポジトリに置くのは、取得ログの CSV（`fetch_logs/`。JPX 担当 107 行、国会図書館・CiNii・J-STAGE 担当 130 行、取りまとめ役の再取得 9 行）と、出典表のメモ（取得日・sha256 先頭 12 桁・確認箇所）、自分の言葉による要約、事実としての数値、短い引用（15 語以内）だけである。**取得物の写しは、著作権に配慮してリポジトリに置いていない**（作業用の保管場所は一時的で、セッションの終了後は残らない）。
- 取引所のデータ提供サービスの利用案内は守った。JPX は、価格の月次 PDF（日報）と適時開示（TDnet）の自動取得をご遠慮願う旨を案内している [PJ-061][PJ-066]。そのため、これらの一括取得は行っていない。

## 8. 検査の記録と、取得ログを使った監査の手順
取りまとめ役（私）が行った検査は次のとおりである。

- 機械照合: ✅P の全行（JPX 70、国会図書館・CiNii・J-STAGE 関連の 131）で、URL（または「取得 #N」）、sha256 の先頭 12 桁、保存ファイルの実測 sha256、記録 ID、メモ中の ISBN と「」内の語が、取得ログと保存ファイルに合うことを確かめた。不一致は 0 件だった。検査が緩くないことは、書籍表の複製に年・出版者・題名・著者の誤りを混ぜて検出できることで確かめた。
- 内容の照合: 日本語書籍の表 104 行（邦訳 46 行・専門書 58 点）を NDL の取得物と、論文表 39 行（抄録を読んだ分）を CiNii／J-STAGE の取得物と一件ずつ照合した（題名・出版者・年・責任表示、誌名・巻・頁・DOI、言い換え欄の数値が抄録にあること）。不一致は 0 件で、抄録の長い転載もなかった。
- 独立した再取得: JPX の主要ページ、J-STAGE の論文ページ 2 件（sha256 が担当の記録と完全に一致）、CiNii の検索応答（該当記録が同一）、NDL の「一目均衡表」の検索（6 冊、一致）を、別に取得して照合した。

監査の手順は次のとおり。
取得ログは `fetch_logs/` にある（列: 通番、URL、取得時刻（UTC）、HTTP 状態、バイト数、sha256、作業用ファイル名）。作業用ファイル名は取得時の保管場所のもので、リポジトリにはその実物はない。

1. 出典表から確かめたい行を選ぶ（例: PJ-006）。
2. `curl -sS -L -A "research-fetch/1.0" -o x.html "<URL>"` で再取得し、`sha256sum x.html` の先頭 12 桁を、メモの `sha256:` と比べる。
3. 一致すれば、記録した版と同じものを読んでいる。**不一致でも誤りとは限らない**（JPX のページは更新され、動的に変わる部分もある）。その場合は、ページの更新日と、メモの「確認箇所」にある語句・数値が今も同じかを見る。
4. 取得ログの sha256 は 64 桁で、出典表のメモは先頭 12 桁である。取得ログに 404・429・500 の行があるのは、それも取得回数に数えたためである。
5. **国会図書館サーチ・CiNii の書誌・論文の行は読み方が違う。** URL は記録のページ（`…/books/R100000002-I…`、`…/crid/…`）だが、sha256 は、その記録を含む検索応答（OpenSearch）の取得物のものである。メモの「取得 #N」が `ndl_cinii_jstage_fetch_log.csv` の通番 N の行を指すので、その行の URL を取得し、応答に記録の ID があるかを確かめる。J-STAGE の論文ページの行は、URL がそのまま取得したページである。
