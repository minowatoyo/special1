# W3 実行前の修正と実行手順（承認範囲: 取得・保存・品質検証まで）

実取得は**利用者のローカル PC**で行う。共有セッションでは実行しない。W4・W5・モデル既定の変更には進まない。

## 修正点
1. **普通株の判定**: `is_domestic_common = ProdCat=="011" and len(Code)==5 and Code[-1]=="0"`（コードは文字列。欠損・不正は除外）。市場区分の判定（`market_in`）とは別実装。テスト: 末尾非 0 の 011、ETF（013）・REIT（014）、欠損・不正コード、英字を含むコード（例 `130A0`）。
2. **取得と母集団選定の分離**: 取得は日付指定の全銘柄。普通株・市場区分・流動性は `schema.universe`（後段）。2022-04-04 前の母集団は案として `docs/universe_change_proposal.md`（未確定）。
3. **上場銘柄表は営業日ごと**: 日次スナップショットを保存。加工後は有効区間（`valid_from`／`valid_to`）に圧縮（`schema.master_intervals`）。テスト: 月中の新規上場・上場廃止・市場変更、スナップショットの欠け。
4. **実行条件**: (a) 開始時に契約期間を再確認し、2016-11-12 と違えば自動で変えず停止（`check_contract`）。(b) チェックポイント `_meta/checkpoint.jsonl` は、全ページ取得に成功した後にだけ追記（fsync）。中断・再開で重複・欠落なし（テスト）。(c) ページ分割は全ページ取得し、ページ数とファイルを記録。(d) 失敗（200 以外、壊れた本文、営業日の日足・銘柄表・指数が 0 行）は未完了のまま最大 3 周で再試行し、報告。財務サマリーの 0 行は件数付きで受け入れ（`zero_rows`）。429 は停止。(e) 加工は、チェックポイントに載った完了分のページだけを使う。

## 追加修正（W3 承認時）
- **終了日**: 実行日の前営業日（土日を除く）に固定。当日分は未確定のため取得しない（`--end` はそれより後を指定できない）。
- **0 行が解消しない営業日**: 3 周しても解消しない日は、全体を止めず `_meta/investigate.jsonl` に「要調査」（日付・エンドポイント・理由）として記録し、残りを進める。正常な 0 行としてはチェックポイントに載せない。`report_w3.py` が一覧を出す（後の再実行で解消した日は一覧から消える）。
- **日付の検証**: 上場銘柄表・銘柄日足・指数日足は、返った行の日付が要求日と一致するか検証し、不一致は `date_mismatch` としてチェックポイントとレポートにフラグを付ける（データは保存したまま）。
- **保存方式**: 生データは無圧縮のまま。
- `remaining_if_rerun` は、要調査に載った件を除く未完了数（0 になるはず）。要調査の件数は `investigate_not_completed` に別掲し、再実行すると再試行される。

## 実行手順
```
export JQUANTS_API_KEY=...            # Windows は $env:JQUANTS_API_KEY="..."
python scripts/jquants/backfill.py            # 計画の確認
python scripts/jquants/backfill.py --execute  # 実取得（中断しても同じコマンドで再開）
python scripts/jquants/build_processed.py
python scripts/jquants/report_w3.py           # 完了報告用の集計
```
`report_w3.py` の出力（取得期間、エンドポイント別の成功件数・行数・ページ数、非 200 の応答、銘柄数、欠損、品質フラグ、調整係数の突合、保存容量、ハッシュ、再実行時の残り件数）を貼ってください。生の表は不要です。再開試験は、途中で中断して再実行し、`remaining_if_rerun` が 0 になること、再々実行で取得 0 件になることで確認します。

## データ管理
`data/jquants/`（git 管理外）。生データ・加工後の表は、会話・公開レポート・外部 LLM に出さない。解約時は `sh scripts/jquants/purge.sh --yes`。
