# チェックリストとテンプレート（分析メモ・ルール仕様書・バックテスト・日誌）
> 要約: 分析の再現性と検証の質を上げるための雛形集。(A) 分析メモ、(B) 検証可能なルール仕様書、(C) バックテスト設計チェックリスト（先読み・生存者バイアス・コスト・日本株固有）、(D) 新しい指標・パターンの審査票、(E) 取引日誌の列定義、(F) 定期レビューの問い。コピーして使う。
> 最終更新: 2026-11-09

## B. ルール仕様書のテンプレート（機械的に検証できる形）

曖昧さが残るルールは検証できない。次の欄をすべて埋められるか確認する。

| 欄 | 記入内容（例） |
|---|---|
| ルール名・版 | 20日高値ブレイク v1 |
| ユニバース | 対象市場・区分、除外条件（売買代金が基準未満、新規上場から○日以内など）、**上場廃止銘柄を含める** |
| データ | 価格（調整後／未調整）、頻度、期間、出所、欠損・異常値の処理 |
| シグナル定義 | 数式（`close > max(high[t-20:t-1])` のように、どの足のどの値を使うか） |
| 判定タイミング | 「当日の終値確定後」。当日の足の確定前の値を使わない |
| 約定の仮定 | 翌営業日の始値／指値／逆指値。約定しない場合（ストップ高張り付き等）の扱い |
| 損切り・利確 | 価格・ATR倍率・時間切れ。判定は足の確定後か、ザラ場の逆指値か |
| ポジションサイズ | 固定金額・固定リスク（損切り幅から逆算）・均等配分。売買単位への丸め |
| 保有制約 | 同時保有銘柄数、1銘柄の上限、現金比率 |
| コスト | 手数料、スリッページ（売買代金・板の厚みに依存）、信用の金利・貸株料・逆日歩、税 |
| 評価指標 | 総損益だけでなく、最大ドローダウン、勝率と平均損益比、取引回数、期間別の成績 |
| 検証計画 | 学習／検証期間の分割、ウォークフォワード、試すルール・パラメータの数（記録） |

## C. バックテスト設計チェックリスト

☐ は実行前に必ず確認する。

### C-1. 先読み（look-ahead）
- ☐ シグナルは足が確定した後に判定し、約定は**それより後**の価格にしている（当日終値で判定して当日終値で約定させていない）。
- ☐ 一目均衡表の遅行スパン、未来の雲、将来の値で確定する指標を判定に使っていない。
- ☐ ジグザグ・スイング高安・パターン検出は、**確定足以降**にのみ使っている（転換点は後から分かる）。
- ☐ 週足・月足を日足に結合するとき、期間の途中で「確定した週足・月足の値」を参照していない（リサンプルでの漏れ）。
- ☐ 決算・財務データは「公表された日以降」にのみ使っている（期末日付で参照していない）。
- ☐ 指標の計算を時点 k で打ち切っても過去の値が変わらないか、自動テストで確認した（[参考実装のテスト](../07_reference_code/tests/test_causality.py)）。

### C-2. データ
- ☐ **生存者バイアス**: 現在上場している銘柄だけでなく、上場廃止・合併・倒産した銘柄を含む。
- ☐ 分割・併合・配当の調整方式を確認した。**価格水準に依存する条件**（キリ番、呼値、価格フィルタ、株価に対する値幅）は、調整後価格だと当時の水準とずれる。未調整価格での再検証をした。
- ☐ 出来高ゼロ・欠損・異常値・休場日の扱いを定義した。
- ☐ 時間帯: 取引時間・時間外（PTS）・タイムゾーンを揃えている（分足・ザラ場を使う場合）。

### C-3. 約定とコスト
- ☐ ストップ高・安、特別気配、寄付前の板寄せなどで**約定できない日**を扱っている（約定したことにしない）。
- ☐ 注文サイズが当日出来高に対して現実的（例: 当日出来高のごく一部）。大きすぎる注文はスリッページが急増する。
- ☐ 呼値の単位による価格の刻み、売買単位（単元株）による株数の丸めを反映した。
- ☐ 手数料・スリッページを入れ、さらに**コストを2倍にしても**結論が変わらないか見た。
- ☐ 空売り・信用取引: 金利、貸株料、逆日歩、期日、空売り規制を反映した。
- ☐ 税・配当の扱いを方針として決めた（配当落ちの価格調整と整合させる）。

### C-4. 統計
- ☐ 取引回数が十分か。パラメータ数に対してデータ量が少なすぎないか。
- ☐ 同じデータで**試したルール・パラメータの総数**を記録した（多重検定。試行が多いほど「偶然の好成績」が出やすい）。
- ☐ 期間を分け、検証期間は一度だけ見た。ウォークフォワードで再最適化の手順も含めて検証した。
- ☐ 総損益だけでなく、ドローダウン、最悪の連敗、損益の分布（少数の大勝ちに依存していないか）を見た。

### C-5. 頑健性
- ☐ パラメータを±20%程度動かしても、性質が大きく変わらない（尖った最適値に依存しない）。
- ☐ 別の銘柄群・別の期間（上昇相場／下落相場／横ばい）で成績を確認した。
- ☐ 手法の性質に合うベンチマーク（バイ・アンド・ホールド、同じリスクの単純ルール）と比較した。
- ☐ 結果が弱い、条件に敏感、コストで消える場合は**採用しない**と事前に決めた。

## D. 新しい指標・パターンを導入するときの審査票

| 問い | 判定 |
|---|---|
| 定義は曖昧さなく数式・手順で書けるか（人によって引く線が変わらないか） | はい／いいえ |
| 計算の流儀（平滑化、初期値、標準偏差の自由度）をツールと突き合わせたか | はい／いいえ |
| 先読みがないか（打ち切りテスト、確定足の扱い） | はい／いいえ |
| 既に使っている指標と同系統でないか（冗長性） | はい／いいえ |
| パラメータはいくつか。それぞれを選んだ理由と、動かしたときの感度は | 記述 |
| どの市場・期間・銘柄群で検証したか。日本株で固有の制度の影響は | 記述 |
| 失敗パターンと、そのときの損失の上限は | 記述 |
| 学術・実証の根拠は何か。反証はあるか（`../03_evidence/`） | 記述 |

## E. 取引日誌の列定義（CSV）

```csv
id,date_entry,code,name,side,timeframe,setup,thesis,trigger,invalidation,planned_stop,planned_target,risk_amount,shares,entry_price,date_exit,exit_price,exit_reason,fees_slippage,pnl,r_multiple,followed_plan,chart_ref,notes
```

- `r_multiple` = 損益 ÷ 想定リスク（損切りまでの金額）。勝ち負けの大きさを揃えて比較する。
- `followed_plan` = 計画どおりだったか（Y/N）。計画を破った取引を別に集計すると、手法の問題か実行の問題かを切り分けられる。
- `chart_ref` = 分析時点のチャート画像のファイル名（後知恵を防ぐため、**当時の画像**を残す）。

## F. 定期レビューの問い（月次・四半期）

1. 計画どおりに実行できた取引の割合は。破った理由は。
2. 手法別・銘柄タイプ別・市場環境別の成績に偏りはないか。
3. 損切りは計画どおりの位置で執行されたか。ギャップ・約定不能で想定を超えた損失はなかったか。
4. 実際のコスト（手数料・スリッページ）は、検証で仮定した値と比べてどうか。
5. 見送った取引で、見送らなければ良かった／悪かったものを後知恵抜きで評価するとどうか。
6. 手法を変える前に、変更案を過去データで検証したか（直近の成績に引きずられた変更ではないか）。
